01 연구 목적 및 가설

프롬프트 엔지니어링 수준의 차이가 바이브 코딩으로 생성된 웹 서비스의 기능 구현 정확도, 실행 안정성, UI 구성 완성도, 모바일 대응, 추가 기능에 차이를 만드는지를 비교한다.

연구 해석의 범위: 본 연구의 C·D 조건은 선행 연구의 원칙을 적용한 실험 조건이지, 해당 논문이 학교 웹 서비스 개발 성능을 직접 검증했다는 의미는 아니다. 결과는 “프롬프트 조건과 구현 결과 사이에서 관찰된 차이”로 기술하며, 단일 모델 실험에서는 모델 간 일반화 주장을 하지 않는다.
구분 내용
독립변인 프롬프트 조건 A·B·C·D 및 입력 언어 한국어·폴란드어·태국어
통제변인 ChatGPT 단일 모델, 공통 과제, 프롬프트 원문/번역본, 새 채팅, 실행 횟수, 브라우저 환경, 평가 절차
종속변인 100점 총점과 5개 하위 영역 점수
가설 A→B→C→D 순으로 평균 구현 완성도가 높아지는 경향이 관찰될 수 있다. 단, 결과 확인 전 방향성이나 인과관계를 확정하지 않는다.

03 실험군 구성

A — 최소 입력 기준선

프롬프트 엔지니어링이 거의 없는 대조 기준.

B — 일반 사용자 수준

기본 요구사항을 직접 제시한 일반적 입력.

C — 논문 기반 조건

선행 연구의 원칙을 본 실험 조건에 선정·조합.

D — C + SNS 이슈 조건

C 조건에 비교 자극·심호흡·중요성 과장 추가.

이번 연구는 ChatGPT만 사용하므로 모델 효과는 분석 대상이 아니다. 분석의 중심은 A–D 프롬프트 조건 × 언어 조건이다.

04 실험 방법

  1. 실험 시작 전에 사용할 ChatGPT 모델을 하나로 고정하고, 모델 선택이 자동 변경되지 않았는지 확인한다.
  2. 같은 날 가능한 짧은 시간 범위 안에서 전체 조건을 수행한다. 장시간에 걸쳐 나누지 않는 것을 원칙으로 하여 모델·서비스 업데이트 영향 가능성을 줄인다. 업데이트를 임의로 차단하려 하지 말고, 변경이 발견되면 반드시 기록한다.
  3. 시크릿 창을 사용한다. 필요 시 개발자 도구를 열고 Application/Storage → Clear site data를 실행하여 쿠키·스토리지·localStorage 등을 초기화한다.
  4. 새 채팅을 시작하고, 다른 대화의 내용·파일·답변을 참조하지 않는다.
  5. A/B/C/D의 잠금된 한국어 원문 또는 사전에 검수하여 동결한 PL/TH 번역본을 그대로 복사한다. 문장 추가·삭제·순서 변경·요약·자연스러운 재작성 금지.
  6. C·D에서 AI가 질문을 하면 사전에 정해둔 후속 프롬프트 원문을 그대로 1회 입력한다. 질문하지 않는 경우 임의의 추가 질문이나 요구사항을 보내지 않는다.
  7. 응답을 결과물로 저장한다. 코드가 여러 메시지에 걸치면 실제 최종 코드 전체를 별도 파일로 보관한다.
  8. 결과물에 대해 아래 표준 채점표를 적용한다. 평가자는 코드 구현 의도를 추측하지 않고 실제 브라우저에서 확인한다.
  9. 평가자 3명 이상이 독립적으로 채점한다. 서로의 점수를 채점 전에 보여주지 않는다.
  10. 모든 원자료(프롬프트, 결과 코드, 실행 화면, 채점 CSV)를 보존하고 임의 결과 삭제는 하지 않는다.
  11. 브라우저 확장 기능, 번역기, 자동완성 등 실험에 영향을 줄 수 있는 도구의 사용 여부도 전 조건에서 동일하게 유지한다.
  12. ChatGPT의 모델·기능·정책 업데이트를 임의로 차단할 수는 없으므로, 업데이트 영향을 줄이기 위해 가능한 같은 날짜와 짧은 시간 범위 안에서 한 번에 전체 조건을 수행한다. 모델 표시가 바뀌면 해당 시점부터 새 실험 블록으로 기록한다.
중요한 통제: ChatGPT의 웹 검색, 파일 첨부, 이전 대화 문맥 등 추가 정보가 결과에 들어가지 않도록 모든 조건에서 동일하게 유지한다. 모델 UI가 자동 전환되거나 실험 조건이 달라진 경우 해당 실행을 그대로 숨기지 말고 별도 기록한다.
